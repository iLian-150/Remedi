# Remedi v0.5 规格（已拍板，2026-10-07 开工）

起草：2026-10-07。来源：用户 2026-10-07 12:55 CST 提出四项要求（教师端 AI 入口、双端新对话、
发布作业双模式＋练习册知识库、学习报告卡片掉落动画）＋助理同轮提出的两个小优化。
基线：v0.4.0 已上线（2026-10-07 13:33 CST 线上 /api/health 实测 version=0.4.0、provider=cloudflare）。

## 已拍板（2026-10-07 14:22 CST，用户原话：「按方案开干，线下作业要带 AI 批改」）

线下作业本期就接 AI 批改，不做只有打卡的简化版。定版链路：
老师把练习册 PDF 存进知识库 → 发布时选册、填页码、把题目页拍照传上来 →
AI 识别成草稿题，老师扫一眼确认 → 学生逐题拍照作答，走和线上作业
一模一样的批改诊断管线（判分口径统一，仍是 AI 第一次、老师第二次干预）。
原「打卡制先行、AI 批改放下一期」的推荐已被用户否决，勿再按此执行。

## 1. 教师端 AI 入口

现状：Agent 仅学生端有（`backend/app/agent/`，LangGraph StateGraph＋ToolNode；
工具在 `agent/tools.py` 的 `build_tools(db, student)`，只有学生自查三件套）。
教师统计已有 REST：`/teacher/stats/top-questions`、`/stats/knowledge-points`、
`/stats/repair-rate`、`/teacher/students/{id}/profile`（`routers/teacher.py`）。

做法：
- 后端新增 `build_teacher_tools(db, teacher)`，工具复用 stats 服务层，不另写口径：
  ①作业提交情况（某次作业已交/未交名单）②知识点错误率排行 ③班级修复率
  ④某学生画像摘要 ⑤未订正名单。
- 新增路由 `POST /teacher/agent/chat`、`GET /teacher/agent/history`，
  对话落库复用现有 `chat_messages` 表（user_id 通用，无需新表）。
- 前端新增 `views/teacher/TeacherChat.vue`，路由 `/teacher/chat`，左侧导航加「AI 助手」；
  与 `StudentChat.vue` 共用对话组件骨架（抽公共组件，不复制两份）。
- 对话区顶部放快捷提问条：「今天谁没交」「哪个知识点错误率最高」「谁还没订正」，
  点一下即问。
- 验收：教师问「X 作业多少人交了」能答出数字＋未交名单，数字与作业管理页一致；
  教师查不到其他班/其他教师的数据（按 created_by 隔离）。

## 2. 双端「新对话」

现状：历史接口 `GET /student/agent/history` 返回最近 50 条（`_AGENT_HISTORY_RETURN`），
Agent 上下文由 DB 历史喂入；无清理接口。LangGraph checkpointer 未启用，
所以清 DB 历史即清上下文，不涉及图状态残留。

做法：
- 后端新增 `DELETE /agent/history`（双端共用，按当前登录 user_id 删 `chat_messages`）。
- 前端按钮放对话区右上角「＋ 新对话」（不放左侧栏，避免与模块导航混淆），
  点击二次确认后清服务端记录并回到初始简报状态；教师、学生两端位置样式一致。
- 验收：点新对话后刷新页面，历史不回弹；学生清对话不影响教师端记录，反之亦然。

## 3. 发布作业双模式 ＋ 练习册知识库

现状：`assignments` 表只有 title/description/created_by，无 mode、无截止时间；
发布即录题（`POST /teacher/assignments`），学生提交绑定 `questions`。
线下作业没有可承载的数据结构——这是本版主要新基建。

数据变更：
- `assignments` 加列：`mode`（online|offline，默认 online）、`due_at`（可空）、
  `workbook_id`（可空，FK workbooks）、`page_range`（如 "12-14"）、
  `question_nos`（如 "1-8"）、`requirements`（线下作业说明文本）。
- 新表 `workbooks`：id、teacher_id、title、subject、file_path、page_count、created_at。
- 线下学生作答不另建打卡表：题目经教师确认后进入现有 `questions` 结构，
  学生提交复用线上作业的提交/批改表与管线；仅在确需留痕整页原图时，
  沿用现有上传通道与 TEXT 存 JSON 的仓库约定。

流程：
- 发布页第一步先选模式。线上 = 现有录题流程不动。
- 线下 = 选练习册（或先传新 PDF）＋填页码/题号范围＋截止时间＋要求说明。
  PDF 上传存 `backend/uploads/workbooks/`；发布时老师把题目页拍照传上来，
  AI 识别成草稿题，老师确认后才正式发布（题目结构化在本版范围内）。
- 学生端：线下作业出现在作业列表（带「线下」标记），逐题拍照作答，
  走与线上作业一模一样的批改诊断；状态与订正/验证流程与线上一致。
- 教师端：线下作业详情看已交/未交名单，并沿用现有教师纠错/干预入口
  （AI 第一次批改、老师第二次干预）。
- 验收：教师传一本 PDF → 选册填页码、拍照题目页 → AI 出草稿题、教师确认发布 →
  学生逐题拍照作答 → 批改诊断结果与线上作业同口径生成，全链路通。

## 4. 学习报告：数学卡片掉落动画

现状：`StudentReport.vue` 已有科目悬挂卡（`.hang-card`，hover 放大），点数学是即时切换下钻。

做法：
- 点击数学卡：加 `.dropping` 类——挂绳松开效果＋卡片加速下落
  （translateY＋轻微 rotate＋fade，约 450–550ms ease-in），落完再展开报告详情；
  详情区以「从上落下＋小回弹」入场（cubic-bezier 回弹曲线）。
- 保留 `prefers-reduced-motion` 降级：现有样式已有该媒体查询先例，动画在此模式下禁用、
  直接切换内容。
- 验收：点击后动画完整播放一次不卡顿、不闪白；连点不重复触发；详情数据与动画前一致。

## 5. 顺手项（助理提议，用户未反对，随本版带上）
